6.1

一、云安全的定义与常见威胁

6.1.1 云安全的定义

熟悉
云安全（Cloud Security）= 一套融合"技术 + 策略 + 运维"的体系，用于保护云计算环境中的数据、应用、平台、基础设施与账号，保障其机密性、完整性、可用性（CIA 三性），并应对云计算特有风险（多租户、虚拟化、弹性、责任共担）带来的安全挑战。

要理解云安全，先要把握三层含义：

  • ① 目标层面（CIA 三性）：安全的本质目标始终围绕三件事——
    · 机密性（Confidentiality）：数据"不该看的人看不到"（防泄露）；
    · 完整性（Integrity）：数据"不被篡改、不被伪造"（防篡改）；
    · 可用性（Availability）：授权用户"需要时能正常用"（防中断）。
    这三者被统称为 CIA 三元组，是信息安全（含云安全）最基础、最常考的概念。
  • ② 范围层面：云安全覆盖"云上的一切"——底层物理机房与网络、虚拟化层、操作系统、数据库、应用、API、账号与密钥，乃至客户的使用配置。它不是某一款"云防火墙"产品，而是一整套防护组合。
  • ③ 风险层面：云安全在传统信息安全基础上，叠加了云计算独有的新问题：多租户隔离、资源弹性伸缩、责任在厂商与客户间分割、数据跨境等。这是它与传统 IT 安全的根本区别。
  • 传统安全 vs 云安全（对比记忆）：传统安全以"边界防火墙 + 内网可信"为核心假设；云安全因为资源弹性伸缩、边界模糊、访问来自任意地点，更强调"身份即边界"和"零信任（默认不信任，持续验证）"。
  • 一句话范围示例：云安全既管"别人能不能偷看你的数据库"（机密性），也管"数据被改了没"（完整性），还管"服务卡顿打不开怎么办"（可用性）。

6.1.2 常见云安全威胁（CSA 云安全威胁清单）

掌握
最高频的云威胁：配置错误（Misconfiguration）、身份凭证泄露/弱认证、不安全的接口与 API、账户劫持、内部威胁、共享技术漏洞、数据泄露与丢失、拒绝服务（DoS/DDoS）、滥用云服务。

下面按"威胁 → 本质 → 典型场景"逐条拆解，建议优先记前 6 项（考试高频）：

威胁说明（本质）典型场景
① 配置错误
Misconfiguration		存储桶/安全组/端口被错误开放为公网。云上"头号"事故源，且多属客户责任对象存储设为公开可读，导致用户数据被全网爬取；数据库端口对 0.0.0.0/0 开放无密码
② 身份凭证泄露
/ 弱认证		密钥、密码、AccessKey/SecretKey 泄露，且无 MFA 保护开发者把 AK/SK 提交到 GitHub，被恶意扫描利用来挖矿；长期密钥写进前端代码
③ 不安全的接口/APIAPI 未鉴权、未限流、存在越权/注入漏洞越权接口可遍历他人订单 ID 获取隐私；未限流接口被刷爆
④ 账户劫持
Account Hijacking		通过钓鱼/撞库夺取管理员或用户账号钓鱼邮件骗取控制台登录，进后台删库勒索
⑤ 内部威胁
（恶意/失误）		内部人员越权访问、数据外泄或误操作离职员工带走数据；运维误删生产数据库
⑥ 共享技术漏洞底层虚拟化/容器隔离被突破，跨租户越权同宿主机"邻居"通过侧信道或漏洞读到你的内存数据
⑦ 数据泄露 / 丢失数据被窃取，或误删、无备份导致永久丢失勒索软件加密数据；误删库且无备份
⑧ 拒绝服务
DoS / DDoS		海量流量打满入口，导致服务不可用大规模请求冲垮 Web 入口，业务停摆
⑨ 滥用云服务用盗用的云资源做攻击跳板（挖矿、钓鱼、外发垃圾）攻击者用盗用的账号对外发起攻击
  • 配置错误示例：某公司把云数据库 3306 端口对 0.0.0.0/0 开放且未设密码，被勒索组织拖库——这是"客户侧责任"，云服务商（CSP）不背锅。
  • 凭证泄露示例：把长期有效的 Secret Key 写进前端代码，等于把家门钥匙挂在门口任人取用。

6.1

二、云计算环境中安全问题的复杂性与多样性

6.1.3 复杂性与多样性的来源

熟悉
云安全"更复杂、更多样"的根本原因：边界消失、多租户共享、责任共担、资源弹性、合规跨境、攻击面叠加（虚拟化 + 容器 + API + 供应链）。这六个因素叠加，使云安全远难于传统 IT 安全。

逐一理解每个来源为何"制造难度"：

  • ① 边界模糊（去边界化）：传统安全靠"内网可信、外网危险"划边界；云上访问来自任意终端、任意地点、任意网络，固定边界失效 → 必须转向"零信任"（默认不信任、持续验证）。
  • ② 多租户隔离：同一物理机/同一套虚拟化平台跑着多家客户的数据。隔离机制（虚拟化、容器、网络微隔离）一旦失效，就会"串门"，对底层技术安全提出极高要求。
  • ③ 责任共担：安全职责在 CSP 与客户之间分割，双方都容易以为"对方负责" → 出现"责任真空"（谁都没管的那块）。
  • ④ 弹性与动态：资源随时创建/销毁，资产盘点、日志审计、配置基线难以稳定，影子 IT（未被纳管的临时资源）丛生，攻击面随时变化。
  • ⑤ 合规与数据主权：数据可能落在境外机房，要同时满足等保、《网络安全法》《数据安全法》《个人信息保护法》以及境外的 GDPR 等多套法规，冲突时还需权衡。
  • ⑥ 攻击面叠加：IaaS 的虚拟化层、PaaS 的运行时、SaaS 的接口，再加第三方依赖/开源组件/供应链，攻击面比传统 IT 更广、更碎。
图 6-2（6.1）复杂性六大来源：六因素相互交织，使云安全难度倍增

6.1.4 复杂性在实践中的具体表现（"多样性"体现在哪）

熟悉
多样性 = 同样的"上云"，不同服务模型（IaaS/PaaS/SaaS）、不同行业、不同部署形态（公有/私有/混合）面临的安全工作天差地别，不存在"一套方案包打天下"。
维度带来的"多样性"安全重心差异
服务模型不同IaaS 客户要自己管 OS/补丁；SaaS 几乎全交给厂商IaaS 重系统层，SaaS 重账号与使用配置
行业合规不同金融/政务强合规，电商/个人应用相对宽松前者要等保三级 + 密钥自管(BYOK)，后者可简化
部署形态不同公有云、私有云、混合云混合云要额外解决"跨云统一身份与策略"难题
数据敏感度不同公开资料 vs 个人敏感信息 vs 国家机密敏感数据需加密、脱敏、分级访问
  • 多样性示例：同样叫"上云"，用 IaaS 自己装系统（客户责任大、要会的多）和用 SaaS（只管账号）面临的安全工作量天差地别——这就是"多样性"。
  • 复杂性示例：一家跨国企业用公有云 + 本地私有云的混合架构，既要防外部攻击，又要满足"中国数据不出境、欧盟满足 GDPR"，还要统一身份——复杂度陡增。
⚠ 考试易错点："复杂性与多样性"是云安全区别于传统安全的核心特征，答题时务必点出"责任共担 + 多租户 + 边界消失"这几个关键词，不能只泛泛说"网络有风险"。

三、云安全对于云计算的重要性

6.1.5 为什么云安全是云计算的"生命线"

熟悉
没有安全就没有信任，没有信任就没有上云——云安全直接决定了云计算能否被采用、能否合规、能否持续运营。它是云计算的"生命线"。
  • ① 数据是核心资产：云上集中存放大量敏感数据（用户隐私、商业机密、资金信息），一旦泄露代价极高——声誉受损、监管罚款、法律诉讼，往往不可逆。
  • ② 业务连续性依赖可用性：越来越多的核心业务跑在云上，一次 DDoS 或勒索导致的中断，直接转化为营收损失与客户流失。
  • ③ 合规是硬约束：金融、政务、医疗、教育等行业上云必须满足等保/行业监管，安全不达标就"不能上线"，云安全是准入门槛而非可选项。
  • ④ 信任是采用前提：企业是否敢把核心系统搬到云，取决于对云服务商安全能力的信任；安全事件会直接动摇整个市场的采用意愿。
  • ⑤ 共享放大效应：云的"多租户"特性意味着一处基础性漏洞可能影响大量客户，安全已成为云生态的公共基础设施。
图 6-3（6.1）云安全重要性：底层是生命线，向上支撑资产/合规/可用性，最顶层是信任

6.1.6 再强调：安全是"双方责任"，不是买云就自动安全

掌握
云安全的核心原则——责任共担：CSP 负责"云本身的安全"（底层基础设施、硬件、虚拟化），客户负责"云中的安全"（操作系统、应用、数据、身份与访问配置）。安全不会因为你买了云服务而自动生效。
云服务商（CSP）负责"云本身安全"客户负责"云中安全"
物理机房、电力、网络骨干自身业务系统、应用的漏洞与配置
虚拟化层 / HypervisorGuest OS、补丁、主机加固
底层硬件与存储可靠性数据库中的数据、数据加密与备份策略
云控制台平台自身的安全账号、密码、访问密钥、权限分配（IAM）
⚠ 考试易错点（必考）：无论哪种服务模型（IaaS/PaaS/SaaS），"数据加密与客户端配置、身份管理"始终属于客户责任——云厂商不会替你设好密码和权限。把"配置错误""密钥泄露"当成了"厂商的问题"，是考试中最典型的错误理解。
  • 一句话总结重要性：云安全做不好 → 数据泄露/业务中断 → 不合规不能上线、客户不信任 → 云计算的价值（弹性、低成本、敏捷）就无从谈起。所以"安全是云计算的生命线"。
