6.3 身份、授权和访问管理（IAM）

第6章 云计算安全 · 身份认证 | 权限管理 | MFA | 云中 IAM 的重要性与实现方式

一、身份认证、权限管理和 MFA 的基本概念 掌握

1.1 身份认证（Authentication, AuthN）

认证回答："你是谁？"——验证用户或服务的身份是否真实。

三类认证因素（"你知道什么、你有什么、你是什么"）：

因素类型说明示例
知识因素（Something you know）只有用户知道的信息密码、PIN 码、安全问题答案
持有因素（Something you have）用户持有的物理设备或数字凭证手机（短信验证码）、硬件 Token、智能卡、数字证书
固有因素（Something you are）用户生物特征指纹、人脸、虹膜、声纹

1.2 授权（Authorization, AuthZ）

授权回答："你能做什么？"——决定已验证的用户或服务可以访问哪些资源、执行哪些操作。

四大授权模型：

模型原理适用场景
DAC（自主访问控制）资源所有者自行决定谁可以访问个人文件共享
MAC（强制访问控制）系统根据安全标签强制控制，用户无法绕过军事/机密系统
RBAC（基于角色的访问控制）权限绑定到角色，用户通过角色获得权限企业应用、云 IAM 的默认模型
ABAC（基于属性的访问控制）根据用户属性、资源属性、环境条件动态判定权限零信任架构、精细化云策略
最小权限原则（Least Privilege）：用户或服务仅被授予完成任务所需的最小权限集合。这是信息安全中最基础也是最容易被忽略的原则。

1.3 MFA（多因素认证 Multi-Factor Authentication）

MFA 要求用户提供两种及以上不同类别的认证因素才能通过认证。即使密码泄露，攻击者仍无法通过 MFA。
  • 弱 MFA：密码 + 短信验证码（虽然两个因素，但短信可被 SIM Swap 攻击劫持）。
  • 强 MFA：密码 + TOTP（基于时间的一次性密码，如 Google Authenticator）+ 硬件安全密钥（如 FIDO2 / U2F 标准）。
Google 在 2017 年强制要求所有员工使用硬件安全密钥后，员工账号被钓鱼攻击的成功率下降至零。这证明了强 MFA 的有效性。

二、身份访问管理在云计算环境中的重要性和实现方式 掌握

2.1 云计算中 IAM 的核心重要性

  • "身份即边界"（Identity is the New Perimeter）：传统网络有物理防火墙作为边界；云环境中资源分布在多个可用区/地域，不存在固定的网络边界。身份认证和授权成为第一道也是最重要的一道防线。
  • API 驱动：云上的一切操作（创建实例、修改配置、读取数据）都通过 API 执行。API 密钥（AK/SK）的泄露等同于云账户的完全失控。
  • 多租户环境：同一云平台上的不同用户通过 IAM 进行身份与资源隔离。IAM 配置错误（如过度授权）是数据泄露的头号原因。
  • 合规要求：等保 2.0 的"安全计算环境"和"安全区域边界"中明确要求对用户身份进行标识与鉴别，对访问进行控制。
  • 责任共担：CSP 提供 IAM 工具，但用户负责正确配置 IAM 策略。CSP 不会替你审查权限是否过度。

2.2 云 IAM 的核心组件

组件功能云厂商示例
用户（User）长期凭证（用户名+密码 / AK/SK）AWS IAM User / 阿里云 RAM 用户
角色（Role）临时凭证，用于跨服务授权或联合身份AWS IAM Role / 阿里云 RAM 角色
策略（Policy）JSON 格式的权限声明：允许/拒绝什么操作、针对什么资源、在什么条件"Effect":"Allow","Action":"s3:GetObject"
组（Group）将用户分组并统一授权，配合 RBAC 使用AWS IAM Group / 腾讯云 CAM 用户组
联合身份使用企业 IdP（如 AD / LDAP / Okta）通过 SAML 或 OIDC 登录云平台AWS SSO / 阿里云 SSO

2.3 云 IAM 的最佳实践

  1. 绝不使用根账号（Root Account）做日常操作。创建单独的管理员用户，根账号仅用于需要根权限的极少数操作（如更改账户设置）。为根账号强制启用 MFA。
  2. 使用角色而非长期 AK/SK：跨服务调用（如 EC2 读 S3）应使用 IAM Role 获取临时凭证，而不是在代码中硬编码 AK/SK。
  3. 最小权限 + 定期审查：使用 IAM Access Analyzer 或类似工具定期审查权限，删除未使用的角色和过度宽泛的策略（如 Resource:"*"）。
  4. 策略条件：利用条件键（Condition）细化权限。例如：只允许从公司 IP 地址段登录（IP 白名单）、只允许通过 MFA 认证后执行敏感操作。
  5. 联合身份 + SSO：与企业身份源（AD / Okta / Azure AD）集成，实现员工入职自动开通权限、离职一键回收。
  6. 审计与告警：开启 API 日志，设置异常告警（如从未使用过的 Region 发起操作、失败登录次数超过阈值）。

2.4 常见云 IAM 实现方案对比

云厂商IAM 服务名核心特色
AWSIAM + IAM Identity Center策略颗粒度最细（到 API 级别）；Access Analyzer；支持 ABAC（基于标签的访问控制）
阿里云RAM（资源访问管理）与阿里云 SSO 和 AD 集成；支持 RBAC 角色；操作审计 ActionTrail
华为云IAM（统一身份认证）企业项目（EPS）粒度管理；支持 SAML / OIDC 联合身份；多因素认证 MFA
腾讯云CAM（访问管理）策略语法与 AWS 类似；角色、用户组、策略三件套；支持企业微信/SAML/OIDC 联合
⚠ 常见错误：在代码或配置文件中硬编码云 API 密钥（AK/SK），导致密钥被泄露到 GitHub 等代码仓库。正确做法：在 IaaS 上使用实例角色、在开发环境中使用临时令牌（STS Token）。

2.5 身份管理闭环

一个完整的云 IAM 生命周期：身份源同步 → 权限建模（RBAC + ABAC）→ 访问请求 → 审批 → 分配/回收 → 周期性审计（"谁，在什么时候，访问了什么，做了什么"）。整个过程必须可审计、可追溯、可自动化。
