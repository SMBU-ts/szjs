① AWS 概述：云计算商用先驱

熟悉
核心概念

地位：亚马逊 AWS 是现代商用云计算的开创者。2006 年同时推出 EC2（弹性计算云） 与 S3（简单存储服务），被视为现代云计算诞生的标志。

核心特征：按需自助、泛在网络访问、资源池化、快速弹性、按使用量计量（对应 NIST 五大特征）。具备全球多区域（Region / AZ）、规模效应低成本、成熟服务生态。

② 基础存储架构 Dynamo（★本节核心）

熟悉
Dynamo 是什么

亚马逊为「购物车」等核心业务自研的 高可用、可水平扩展的分布式键值（Key-Value）存储。经典论文 Dynamo: Amazon's Highly Available Key-value Store（SOSP 2007）。

CAP 取舍：在 CAP 定理中选 AP（可用性 + 分区容忍），牺牲强一致性 → 最终一致性。设计哲学：宁可返回稍旧的数据，也绝不让服务下线，即「永远可写 / 永远可读」。

五大核心技术
技术作用一句话考点
一致性哈希按 key 分片到哈希环；用「虚拟节点」均衡负载避免普通哈希扩容时的海量数据迁移
复制 Replication每个 key 存 N 份，落到协调者顺时针后继的 N-1 个节点（默认 N=3）无单点故障，任意节点宕机仍有副本
向量时钟
Vector Clock		用 [节点:版本号] 列表记录更新的因果关系多副本冲突时判断先后、如何合并
Quorum配置 R（读副本数）、W（写副本数），要求 R+W>N可调一致性强度；W=N 偏写可用，反之偏读一致
Hinted Handoff
提示移交		副本节点宕机时由其他节点代管，恢复后再移交实现「永远可写」的关键兜底（sloppy quorum）

补充：节点间用 Gossip 协议做去中心化成员管理与故障检测；用 Merkle 树做副本差异比对与「反熵（anti-entropy）」同步。

③ 主要服务（考试四件套）

熟悉
四大核心服务
服务类别说明计费 / 特点
EC2
弹性计算云		计算（IaaS）可弹性伸缩的虚拟机，按需启停按小时计费，云=租服务器的最直观体现
S3
简单存储服务		存储对象存储（Bucket/Object），持久性 11 个 9无限扩展；借鉴 Dynamo 高可用思想

关系型数据库		数据库托管 MySQL/PostgreSQL/Oracle/SQL Server 等自动备份、扩容、故障切换
Lambda
无服务器计算		Serverless事件驱动，上传代码由 AWS 在触发时运行按调用次数 + 执行时长计费，自动扩缩

④ Dynamo 的影响与平台对比

熟悉
Dynamo 的辐射
  • S3、DynamoDB 都借鉴了 Dynamo 的高可用思想；DynamoDB 可视为 Dynamo 思想的商业化托管版。
  • 开源界受其启发诞生 Cassandra、Riak、Voldemort 等。
平台路线对比（易连考）
平台核心技术 / 服务
GoogleGFS（分布式文件系统）+ MapReduce（批处理）+ BigTable（列式 NoSQL）+ Borg（K8s 前身）
AWSDynamo（最终一致键值存储，一致性哈希 + Quorum + 向量时钟，S3/DynamoDB 均借鉴）；哲学：宁可返回旧数据也不可下线
华为云鲲鹏算力 + 昇腾 AI + ModelArts + HCS 混合云（政务/金融/制造）
百度云飞桨 PaddlePaddle + AI 开放平台 + 网盘 + Apollo 自动驾驶
考试重点（熟悉）：AWS Dynamo 存储架构（高可用 + 最终一致的分布式键值存储）；一致性哈希 / 复制 / 向量时钟 / Quorum 四大机制；主要服务 EC2、S3、RDS、Lambda 的定位与区别；Dynamo 思想对 S3 / DynamoDB 及开源系统（Cassandra 等）的影响。
易错点速记：
  • ❌ Dynamo 是关系型数据库 → ✅ 是分布式键值存储 + 最终一致。
  • ❌ Dynamo 保证强一致 → ✅ 是最终一致，用 Quorum 调强度。
  • ❌ S3 是块存储 → ✅ 是对象存储（块存储是 EBS）。
  • ❌ Lambda 按实例包月 → ✅ 按调用次数 + 执行时长计费。
  • ❌ 分片用普通哈希 → ✅ 用一致性哈希，避免扩容大量迁移。
样题自测（熟悉层级，单选 / 简答）
1. 亚马逊 AWS 的基础存储架构 Dynamo 属于哪一类存储系统？（ ）
A. 关系型数据库　B. 分布式键值存储　C. 文档型关系库　D. 内存缓存
答案：B。Dynamo 是高可用、最终一致的分布式键值存储。

2. 下列关于 Dynamo 说法，正确的是？（ ）
A. 保证强一致性　B. 采用一致性哈希分片　C. 仅支持单副本　D. 主从同步复制
答案：B。Dynamo 用一致性哈希分片、N 份复制、最终一致、去中心化。

3. 简述 Dynamo 的「永远可写」是如何实现的。
要点：去中心化 + N 份复制（R+W>N 的 Quorum）+ Hinted Handoff（副本节点宕机时由其他节点临时代管、恢复后移交）+ Gossip 故障检测，使部分节点失效时写入仍能被接受。
