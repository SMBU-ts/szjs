2.2 分布式技术 · 详细讲解

云计算关键技术（重点 · 掌握）｜ 分布式系统概念、云中应用、常见技术特点、集群技术

考纲要求：掌握

1分布式系统的基本概念

定义：分布式系统（Distributed System）是由多台通过网络互联的计算机（节点）组成的一个整体， 这些节点协同工作、共享资源，对外呈现为一个统一的、单一的逻辑系统，用户无需关心任务具体由哪台机器完成。

核心思想

  • 分而治之 + 协同：把一个大任务拆给多台机器并行处理，再汇总结果。
  • 对用户透明：用户/应用看到的是"一个系统"，节点的分布、故障、迁移都被屏蔽。
  • 故障独立：单台机器宕机不应导致整个系统崩溃（无单点故障）。

关键特征（掌握，选择题/判断题常考）

分布性

多节点分散在不同位置，通过网络通信。

透明性

位置、迁移、复制、并发对用户不可见。

并发性

多个节点同时处理任务，提高吞吐。

可扩展性

可通过"加机器"水平扩展（Scale-out）。

高可用性

部分节点失效，系统整体仍可服务。

缺乏全局时钟

各节点时钟不完全一致，需逻辑时钟/共识。

易混对比

对比维度集中式系统分布式系统
组成单一主机完成全部任务多节点协同
单点故障主机挂 → 全停单节点挂 → 整体仍可用
扩展方式纵向扩展（换更强单机）横向扩展（加节点）
复杂度低（无需处理通信/一致性）高（通信、一致性、容错）
易混点：① 分布式 ≠ 并行计算——并行计算通常指紧耦合、共享内存的多核/多机（如超算），节点间延迟极低； 分布式节点通过网络松耦合、故障独立。② 集群是分布式的一种典型形态：集群强调"多台同构机器对外像一个整体"， 分布式涵盖范围更广（含异构、跨地域）。两者常被并列考查，区别在于侧重点（见第 4 节）。

2分布式系统在云计算中的应用

本质：现代云计算平台本身就是运行在大规模分布式系统之上的。没有分布式技术， 云就无法实现"资源池化、弹性伸缩、高可用、按需计量"这五大特征。云的底层就是把成千上万台廉价服务器 组织成一个"虚拟超级计算机"。
对应考纲样题："云计算可以把普通服务器/PC 连接起来获得超级计算机般的计算存储能力，且成本更低。" → 正确。 这正是分布式 + 集群技术的核心价值。

三大典型应用（考纲明确列举，必背）

应用领域代表技术 / 系统解决什么问题核心思想
分布式存储 GFS（Google）、HDFS（Hadoop）、Ceph、对象存储 海量数据存不下、单盘易坏 文件分块存储、多副本冗余、跨节点分布，保障容量与可靠性
分布式计算 MapReduce、Spark、Flink 单机算不动 TB/PB 级数据 分而治之：任务拆分到多节点并行算，再汇总（Map + Reduce）
分布式数据库 HBase、Cassandra、MongoDB、TiDB 单机库容量/并发到顶 数据分片（Sharding）到多节点，水平扩展、高并发读写

云中更多分布式支撑技术

分布式文件系统

如 HDFS，为上层计算/数据库提供统一命名空间与高吞吐读写。

分布式缓存

Redis Cluster、Memcached，缓解数据库压力、提升响应速度。

分布式协调

ZooKeeper / etcd，提供配置管理、命名服务、分布式锁、选主（一致性协议 Raft/Paxos）。

分布式消息队列

Kafka、RabbitMQ，解耦生产/消费、削峰填谷、异步处理。

考试重点：云计算的"分布式"应用，考纲只明确要求掌握分布式存储（GFS/HDFS）、 分布式计算（MapReduce）、分布式数据库三条。其余（缓存/协调/消息队列）作了解，能识别即可。

3常见分布式技术的特点

下面按"存储 / 计算 / 数据库 / 缓存 / 协调 / 消息 / 服务"分类，对比各自的核心特点与适用场景。

技术类别代表核心特点典型场景
分布式存储
（文件系统）		 HDFS、GFS、Ceph 数据分块 + 多副本；一次写入、多次读取为主；高吞吐、高容错；适合大文件 海量日志、数据仓库底座、大数据存储
分布式计算 MapReduce、Spark、Flink 任务自动切分并行；Map(映射)+Reduce(归约)；Spark 内存计算更快；Flink 擅长流处理 离线批处理、日志分析、实时流计算
分布式数据库 HBase、Cassandra、MongoDB、TiDB 数据分片跨节点；水平扩展；多为 NoSQL 或 NewSQL；高并发写入 高并发 Web 后端、物联网时序数据、海量 KV 存储
分布式缓存 Redis Cluster、Memcached 内存存储、毫秒级响应；缓存热点数据；集群分片保可用 会话共享、排行榜、秒杀、DB 前置缓存
分布式协调 ZooKeeper、etcd 基于一致性协议（ZAB / Raft）；提供配置、选主、分布式锁；是系统的"神经系统" 微服务注册中心、主节点选举、分布式锁
分布式消息队列 Kafka、RocketMQ 异步解耦、削峰填谷、可靠投递、顺序/重试保证 日志收集、事件驱动、系统解耦
分布式服务框架 Dubbo、Spring Cloud 服务注册发现、负载均衡、容错；支撑微服务架构 大型互联网应用的服务化拆分

分布式系统的"灵魂"：一致性与 CAP 理论（重要考点）

CAP 定理：一个分布式系统无法同时满足以下三者，最多只能满足其中两项： C（一致性）所有节点同时看到相同数据；A（可用性）每个请求都能得到响应； P（分区容错性）网络分区时系统仍能继续工作。
  • 由于网络分区 P 客观上不可避免，实际系统多在 CP（强一致，如 ZooKeeper、HBase）与 AP（高可用+最终一致，如 Cassandra、DNS）之间取舍。
  • BASE 理论：AP 系统的设计哲学——基本可用（BA）、软状态（S）、最终一致性（E）， 即不追求实时强一致，而是经过一段时间后数据达成一致。
考试重点：① CAP 三者名称及含义；② 由于分区不可避免，常见取舍是 CP 或 AP； ③ BASE 是 AP 系统的工程化落地（最终一致性）；④ "最终一致性"是分布式数据库/缓存的典型特征。

4集群技术：特点、类型及应用场景

集群的基本概念

定义：集群（Cluster）是将多台独立的服务器（节点）通过软硬件连接起来，作为一个统一整体对外提供服务的计算模式。 集群中的节点通常同构、位于同一局域网，对外像一个"更强、更稳"的单机。

集群的核心特点

高可用性（HA）

某节点故障，其他节点接管，服务不中断。

负载均衡（LB）

请求分散到多节点，避免单点过载。

可扩展性

加节点即可提升整体能力（水平扩展）。

并行处理

多节点同时算，缩短大任务耗时。

性价比高

用多台廉价 PC 替代小型机/大型机。

易管理

统一调度、统一对外地址/接口。

集群的类型（考纲明确三类，必背）

类型目标工作机制代表 / 场景
高可用集群
（HA Cluster）		 保障服务不中断，避免单点故障 节点间心跳检测；主节点故障，备节点故障转移（Failover）接管 双机热备、数据库主备、关键业务系统
负载均衡集群
（LB Cluster）		 提升并发与吞吐，分摊压力 前置负载均衡器（如 LVS、Nginx）按策略分发请求到后端多节点 Web 服务器集群、API 网关、电商前端
高性能计算集群
（HPC Cluster）		 追求极致计算速度 多节点并行计算同一任务（MPI 消息传递），适合计算密集型 科学计算、气象预报、基因测序、仿真（Beowulf 集群）

应用场景（考纲明确列举）

Web 服务器集群
  • 用负载均衡集群承载高并发访问
  • 节点可水平扩缩，应对流量峰值
数据库集群
  • 主从/多主复制，读写分离
  • 高可用集群保障数据服务不中断

集群 vs 分布式：关系与区别（易考对比）

联系：
  • 集群是分布式系统的一种典型实现形态。
  • 两者都用"多机协作"来突破单机极限。
  • 实际云平台中二者常结合：集群做高可用底座，分布式做存储/计算。
区别：
  • 集群：节点同构、紧耦合，对外像一个更强单机，强调"整体可用/均衡"。
  • 分布式：节点可异构、跨地域，强调"任务拆分到不同机器、各管一块"。
  • 一句话：集群是"多机合一"，分布式是"一任务多机分"。
考试重点：① 集群三类型 = 高可用(Hot Standby/Failover) / 负载均衡 / 高性能计算； ② 场景 = Web 服务器集群、数据库集群；③ 集群特点 = 高可用、负载均衡、可扩展、并行、性价比高； ④ 集群是分布式的子集/实现形态。

★考试速记清单

  • 分布式系统＝多节点协同、对用户透明、无单点故障；特征含分布性/透明性/并发性/可扩展性/高可用/无全局时钟。
  • 云计算=建立在分布式系统之上；三大应用：分布式存储(GFS/HDFS)、分布式计算(MapReduce)、分布式数据库。
  • CAP：一致性/可用性/分区容错 三者不可兼得；P 不可避免 → 取舍 CP 或 AP；BASE=最终一致性（AP 的落地）。
  • 集群＝多台服务器像一个整体；三类型：高可用集群、负载均衡集群、高性能计算(HPC)集群。
  • 集群场景：Web 服务器集群、数据库集群；特点：高可用、负载均衡、可扩展、并行、性价比高。
  • 集群 vs 分布式：集群"多机合一"（同构紧耦合），分布式"任务多机分"（可异构跨域）；集群是分布式的实现形态之一。
  • 样题判断：连接普通服务器获得超算能力且成本更低 → 正确（分布式+集群的价值）。
